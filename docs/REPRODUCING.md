# 评委本地复现说明

## 1. 两种复现范围

**仓库工程演示**：安装固定代码与权重，在本机生成三份程序绘制的输入，真正运行模型并核验原件、区域、时间点和三种报告。任何评委取得仓库及上游模型后都能按此路线尝试复跑。

**历史100套准确率复现**：必须另外取得与历史清单相同 SHA-256 的授权原始图片、视频和编辑真值。仓库没有这些媒体，也没有主办方119张图片。只运行工程样例不能复现或证明97%准确率。离线资料包也必须先确认素材及权重的提供权限，再通过竞赛平台交付。

## 2. 安装、启动、核验

1. 使用 Windows + NVIDIA GPU，参考配置为8GB显存、32GB内存。安装 Python3.12、Git、Node.js20+，升级到兼容 CUDA12.8 的显卡驱动。
2. 下载或克隆仓库，在仓库根目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\安装与初始化.ps1`。该进程会联网安装依赖，克隆上游固定commit并下载约2.3GB模型文件；磁盘还要容纳PyTorch等依赖与解压临时文件。
3. 双击 `启动澄鉴.cmd`。启动器先核对7份运行权重SHA及4个上游commit，再在8765端口本地加载模型；打开 `http://127.0.0.1:8765/`。
4. 检查 `http://127.0.0.1:8765/api/health`：`status` 应为 `ready`，`model_errors` 应为空，图片、视频、多模态、元数据及时序能力应启用。公开版的 `domain_ai_trained=false` 是有意关闭私有辅助头。
5. 在新终端运行 `.\.venv\Scripts\python.exe -X utf8 scripts/reproduce_demo.py --output runs/review-demo-001`。每次选择新的输出目录，脚本不会覆盖历史回执。
6. 查看输出目录的 `summary.json` 与 `records.json`，以及每份输入的掩码、热图、JSON/CSV/HTML报告。退出0表示工程与证据核验通过；还需单独检查超过五秒计数，不代表准确率验收通过。

## 3. 预期输出

| 项目 | 核验依据 |
|---|---|
| 真正完成推理 | 三份输入均为complete；必需分支存在且未失败 |
| 原件未变 | 输入清单、结果及原件下载的SHA相同 |
| 图片区域 | 输出掩码与分析像素尺寸一致 |
| 视频区域 | 每个已采样PTS唯一，掩码时间戳及像素尺寸一致 |
| 风险判定 | 真实推理产生有限的0～1风险值；没有预设分类答案 |
| 导出 | JSON、CSV、HTML均能取得，JSON对应同一原件 |
| 速度 | 每份HTTP上传至终态结果的耗时另列；超5秒保留 |

程序输入并非真实相机照片或生成模型样本，已知复制操作也不保证融合必然报高风险。因此演示验证脚本不以风险高低判成功，不编造真伪精度。

## 4. 常见问题

- 浏览器无法打开：启动终端必须保持运行，模型加载约一分钟，先查看终端错误；不能把127.0.0.1发给另一台电脑当作公网地址。
- 8765占用：停止自己已启动的旧服务，或使用 `.\.venv\Scripts\python.exe scripts/run_local.py --port 8767`，复现命令相应增加 `--base http://127.0.0.1:8767`。
- 权重校验失败：不要忽略错误继续演示。确认网络下载完整，保留损坏文件作排查，再从固定来源恢复。
- GitHub或模型源无法访问：在可访问网络中完成首次初始化，按权限准备离线资料包。国内可访问性尚未作广泛验证。
- 显存不足：先关闭其他模型进程；并行启动两套服务会影响显存与耗时。CPU与不同GPU环境未建立性能承诺。
- 看板没有历史100套：仓库不提供未经授权的历史媒体及其完整案件目录。请参考 `docs/VALIDATION.md`，不要把空看板补成虚构结果。

## 5. 复现与重新训练的区别

使用发布权重即可做工程演示，不需要重新训练。保留的 `scripts/train_*`、`fetch_*`、`prepare_*` 是研究过程代码，依赖对应数据清单、原件、来源排除记录及开发分组；仅克隆源码不能自动恢复完整历史训练环境。数据取得权限、上游字节与固定来源失效时需分别记录，不能静默换成其他数据后继续沿用原准确率。

在仓库根目录运行 `.\.venv\Scripts\python.exe -m pytest -q` 可执行自动测试。这些单元和接口测试验证逻辑，不替代真实模型效果测试。全新第二台机器的安装复现仍待实际验证。
